# Умный Бусел — правила проекта

Обучающее приложение для Жени (5 класс, Беларусь). Windows 11, полностью офлайн. Родитель — не программист: после каждого шага объяснять простым языком и давать команды для PowerShell.

## Стек
Electron + Vite + React + TypeScript, Tailwind 3, Framer Motion, canvas-confetti, Zustand, Zod, Vitest, electron-builder (NSIS, без прав администратора). Шрифт Nunito подключён локально (@fontsource).

## Структура
- `electron/` — main/preload, JSON-хранилище в userData (`data.json`), бэкап при запуске (последние 7).
- `src/engine/` — баллы, уровни, награды (чистые функции, покрыты тестами).
- `src/store/useApp.ts` — состояние и сохранение.
- `src/content/` — Zod-схема и загрузчик. `content/subjects/*.json` — один файл = один предмет, код менять не нужно.
- `src/screens`, `src/components` — интерфейс.

## Контент
- Тексты пишем сами, оригинально. resheba.top и учебники — только как перечень тем. Никаких скраперов.
- Темы математики и «Человек и мир» взяты из оглавлений учебников родителя. Остальные предметы — предварительные, `needsReview: true`.
- Сомнительное (правила белорусского, даты) помечать `needsReview: true`; `CONTENT_REVIEW.md` создаётся командой `npm run validate-content`.
- Белорусские уроки — на белорусском, интерфейс — на русском.

## Этика
Без наказаний, потери баллов за ошибки, таймеров в заданиях и пугающих сообщений. Ошибка: «Почти! Давай разберём». Подсказка 1 бесплатна, 2-я — баллы пополам.

## Награды
Порог по умолчанию 100 баллов, награда по умолчанию «1 час игры на компьютере». PIN по умолчанию 0000.

## Команды (из папки smart-busel)
- `npm install`, `npm run dev` — запуск в окне Electron
- `npm run validate-content`, `npm test`, `npm run build`
- `npm run dist` — установщик в `release/` (на Windows). Основной путь: GitHub Actions `build-busel.yml` → артефакт `umny-busel-installer`.

## Порядок работы
Этапы 1–6 из PLAN.md выполнены; дальше — добавление тем и уроков (см. CURRICULUM_REVIEW.md). Родителю: README_ДЛЯ_РОДИТЕЛЯ.md. После каждого: validate-content, test, build, коммит.

## Правила качества кода
- Я не программист. Объясняй всё простыми словами, команды давай для Windows (PowerShell).
- Перед изменением логики баллов, наград, проверки ответов, сохранения прогресса, родительского режима и PIN — сначала напиши или обнови тест, потом меняй код.
- После каждого изменения запускай все тесты и сообщай результат: сколько прошло, сколько упало, что это значит.
- Если тест падает — ищи причину в коде. Никогда не подгоняй тест под неправильный результат и не удаляй тест, чтобы он «не мешал».
- Исправляй причину ошибки, а не её проявление. Объясни, в чём была причина.
- Не добавляй новое, если задачу можно решить, упростив или удалив лишнее.
- Работай небольшими шагами: один шаг — один коммит с понятным описанием на русском.
- Учебный контент (JSON-файлы с заданиями) и внешний вид не меняй без моей прямой просьбы.
- Новые библиотеки не устанавливай без моего согласия (кроме инструментов для тестов, если я их одобрил).
- Перед крупными изменениями показывай план и жди моего подтверждения.
