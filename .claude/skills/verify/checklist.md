# Чек-лист надёжности по изменениям — для /verify

Пункт срабатывает, только если изменённые файлы подходят под его **признак** (регулярное выражение по путям от корня
репозитория). Обычно срабатывает 2–5 пунктов. Их список печатает `checklist.cjs` (шаг 6 в `run.sh`). Автоматические
пункты он проверяет сам, остальные агент проверяет по описанию и пишет в отчёт.

Изменённые файлы — это разница с `origin/main` плюс незакоммиченные правки.

Формат строки: `| ID | \`признак\` | что проверить | авто | откуда пункт |`. Новый пункт добавляем после каждого
промаха: ошибки, которую нашёл родитель, отката или исправления после выпуска. Устаревшие пункты убираем.
